📖 Grammar Formatting Rules
  • Start Symbol: The Left-Hand Side (LHS) of the first rule is default, or select a custom symbol above.
  • Non-Terminals: Any symbol appearing on the LHS (e.g. E, E', T).
  • Terminals: Symbols on the RHS that do not appear on any LHS (e.g. id, +, *, (, )).
  • Multiple Alternatives: Separate options using the pipe operator |.
  • Epsilon: Write as ε, epsilon, or leave empty.
  • Whitespace: Separate multi-character tokens with spaces (e.g. + T E').

Compiler Construction Theory & Viva Mode

                        
Complete theoretical background, formal LL(1) definitions, and top oral examination (Viva) questions with verified model answers.

                    


                    
                    

                        

                            
                            
                        

                    


                    
                    

                        

                            

                                
1. What is a Compiler?

                                

                                    A compiler translates high-level source code into low-level target machine code or bytecode through sequential analysis and synthesis phases: Lexical Analysis, Syntax Analysis, Semantic Analysis, Intermediate Code Generation, Code Optimization, and Target Code Generation.
                                


                                
2. What is a Context-Free Grammar (CFG)?

                                

                                    A 4-tuple \(G = (V, \Sigma, R, S)\) where \(V\) is a finite set of non-terminals, \(\Sigma\) is a finite set of terminals disjoint from \(V\), \(R\) is a finite relation of production rules \(A \to \alpha\) where \(A \in V\) and \(\alpha \in (V \cup \Sigma)^*\), and \(S \in V\) is the designated start symbol.
                                


                                
3. What is LL(1) Parsing?

                                

                                    L: Left-to-right scan of the input token stream.

                                    L: Leftmost derivation constructed step-by-step.

                                    (1): Exactly one token of lookahead used to deterministically decide which production rule to apply without backtracking.
                                


                                
4. What is Predictive Parsing?

                                

                                    A non-recursive, table-driven top-down parsing technique that maintains an explicit parsing stack. Using the current top symbol and the lookahead token, it queries a 2D matrix \(M[A, a]\) to uniquely identify the correct production.
                                


                                
5. What is FIRST?

                                

                                    For any string of symbols \(\alpha\), \(\text{FIRST}(\alpha)\) is the set of terminals that begin strings derived from \(\alpha\). If \(\alpha \Rightarrow^* \epsilon\), then \(\epsilon \in \text{FIRST}(\alpha)\).
                                


                                
6. What is FOLLOW?

                                

                                    For any non-terminal \(A\), \(\text{FOLLOW}(A)\) is the set of terminals that can appear immediately to the right of \(A\) in some sentential form derived from start symbol \(S\). The end-of-input marker \(\$\) is always placed in \(\text{FOLLOW}(S)\).
                                

                            


                            

                                
7. What is a Parsing Table?

                                

                                    A two-dimensional matrix \(M[A, a]\) where rows represent non-terminals \(A\) and columns represent terminals \(a\) (including \(\$\)). Each entry contains the unique production rule \(A \to \alpha\) to be expanded when the stack top is \(A\) and lookahead is \(a\).
                                


                                
8. How does a Predictive Parser Work?

                                

                                    1. If stack top \(X\) is a terminal and matches lookahead \(a\), pop \(X\) and advance input.

                                    2. If \(X\) is a non-terminal, look up \(M[X, a]\). If entry is \(X \to Y_1 Y_2 \dots Y_k\), pop \(X\) and push \(Y_k \dots Y_1\) in reverse order.

                                    3. If \(M[X, a]\) is blank, report syntax error.

                                    4. If stack top and lookahead are both \(\$\), report ACCEPT.
                                


                                
9. What is Left Recursion?

                                

                                    A grammar has left recursion if \(A \Rightarrow^+ A \alpha\). A top-down predictive parser attempting to expand \(A\) repeatedly without consuming input will enter an infinite loop. Must be eliminated before LL(1) parsing.
                                


                                
10. What is Left Factoring?

                                

                                    When two alternatives for \(A\) share a common prefix \(A \to \alpha \beta_1 \mid \alpha \beta_2\), lookahead cannot distinguish which alternative to pick. Left factoring rewrites it as \(A \to \alpha A'\) and \(A' \to \beta_1 \mid \beta_2\).
                                


                                
11. Advantages & Limitations of LL(1)

                                

                                    Advantages: Deterministic \(O(n)\) time complexity, zero backtracking, intuitive stack operations, small memory footprint.

                                    Limitations: Cannot handle left-recursive or ambiguous grammars; only parses grammars where 1 lookahead token suffices (weaker class than LR/LALR).

                                    Q1: Why is reverse-order pushing required on the parsing stack?
                                    ▼
                                

                                

                                    Because a stack is a LIFO (Last-In, First-Out) structure. To produce a leftmost derivation, the leftmost symbol \(Y_1\) of a production \(A \to Y_1 Y_2 \dots Y_k\) must reside at the TOP of the stack to be processed next. Therefore, symbols must be pushed in reverse: \(Y_k, Y_{k-1}, \dots, Y_1\).
                                

                            


                            

                                

                                    Q2: Can an ambiguous grammar EVER be LL(1)? Why or why not?
                                    ▼
                                

                                

                                    No, absolutely never. An ambiguous grammar by definition possesses at least one string with two distinct leftmost derivation trees. This mathematically guarantees that at least one table cell \(M[A, a]\) will contain multiple competing productions (a conflict), violating the deterministic single-entry requirement of LL(1).
                                

                            


                            

                                

                                    Q3: What causes a FIRST/FIRST conflict versus a FIRST/FOLLOW conflict?
                                    ▼
                                

                                

                                    FIRST/FIRST Conflict: Occurs when two distinct non-epsilon alternatives \(A \to \alpha\) and \(A \to \beta\) share an identical terminal in their FIRST sets (\(\text{FIRST}(\alpha) \cap \text{FIRST}(\beta) \neq \emptyset\)).

                                    FIRST/FOLLOW Conflict: Occurs when a non-terminal has an alternative deriving epsilon (\(A \to \epsilon\)) and another alternative \(A \to \alpha\) where \(\text{FIRST}(\alpha)\) overlaps with \(\text{FOLLOW}(A)\) (\(\text{FIRST}(\alpha) \cap \text{FOLLOW}(A) \neq \emptyset\)).
                                

                            


                            

                                

                                    Q4: Why does the end-marker $ get added to FOLLOW(S)?
                                    ▼
                                

                                

                                    By convention and formal definition, the start symbol \(S\) derives the complete language program. When parsing concludes, the only symbol that can legally follow the entire string is the end-of-input delimiter \(\$\).
                                

                            


                            

                                

                                    Q5: Does eliminating left recursion and left factoring guarantee the grammar becomes LL(1)?
                                    ▼
                                

                                

                                    No. While eliminating left recursion and left factoring are necessary preconditions for an LL(1) grammar, they are not sufficient. The resulting grammar may still have overlapping FIRST/FOLLOW sets or require greater lookahead (\(k > 1\)).
                                

                            


                            

                                

                                    Q6: How does the parser handle epsilon productions on the stack?
                                    ▼
                                

                                

                                    When \(A \to \epsilon\) is chosen from \(M[A, a]\), the non-terminal \(A\) is popped from the stack and nothing is pushed onto the stack. The lookahead pointer is NOT advanced; rather, the underlying symbol underneath \(A\) now becomes the new Stack TOP and is evaluated against the same lookahead token.
